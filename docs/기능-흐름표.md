# 기능 흐름표 (F1~F15)

각 기능마다 **시작하는 쪽**, **기본 흐름**(사용자 → 시스템), **대안 흐름**, **사전·사후 조건**을 적었습니다. 코드(controller, 대화상자)가 실제로 하는 것만 적었고, 따옴표 안의 글은 화면에 나오는 실제 문구입니다.
프로토타입-계획서의 규칙대로, 기본 흐름은 유스케이스 명세의 "기본 흐름", 대안 흐름은 "대안 흐름", 사전·사후 조건은 그대로 명세의 조건으로 옮길 수 있습니다.

공통 사항
- 화면은 모든 요청을 controller(`ScheduleController`, `CategoryController`, `ReminderTimer`)에 넘기고, controller가 리스너로 화면에 결과를 알립니다.
- "저장"이 일어나는 단계(F1·F3·F4·F5·F7)에는 F11 자동 저장이 따라붙습니다. 저장에 실패해도 메모리의 변경은 유지되고 "저장하는 중 문제가 생겼어요" 알림(자세히 버튼)이 뜹니다.
- 지워진 일정을 다루려 하면 "이미 지워진 일정이에요" 토스트를 띄우고 화면을 새로 고칩니다 (일정 찾을 수 없음 공통).

---

## F1. 일정 등록

- **시작하는 쪽**: 사용자 (사이드바 "새 일정", `Ctrl/⌘+N`, 달력의 "이 날에 일정 추가", 빈 시간 찾기의 "이 시간에 추가")
- **사전 조건**: 앱이 실행 중이고 카테고리가 1개 이상 있다 (기본값은 "개인").
- **기본 흐름**
  1. 사용자: "새 일정"을 누른다 → 시스템: 날짜가 채워진 "새 일정" 대화상자를 연다 (시간 09:00~10:00, 카테고리 "개인", 반복·알림 없음).
  2. 사용자: 제목·날짜·시작/끝 시간·카테고리·메모(선택)·반복(F9)·알림(F10)을 입력하고 "저장"을 누른다 → 시스템: 입력값을 검증한다.
  3. 시스템: 같은 시간에 다른 일정이 있는지 본다(F13). 없으면 고유 id(UUID)를 붙여 목록에 넣는다.
  4. 시스템: CSV에 저장하고(F11) 화면을 갱신한다.
  5. 시스템: "일정을 추가했어요" 토스트를 띄우고 대화상자를 닫는다.
- **대안 흐름**
  - 입력 오류: 저장하지 않고 해당 칸 아래에 이유를 보여 준다 — "제목을 입력해 주세요", "제목은 50자까지 쓸 수 있어요", "끝 시간은 시작 시간보다 늦어야 해요", "메모는 200자까지 쓸 수 있어요", "반복 종료일은 시작 날짜보다 빠를 수 없어요", "카테고리를 선택해 주세요".
  - 시간 칸을 읽을 수 없음: "시작 시간을 14:00처럼 입력해 주세요" (끝 시간만, 또는 "시작과 끝 시간을").
  - 취소: "취소" 버튼이나 `Esc`로 닫는다. 아무것도 저장하지 않는다.
  - 시간이 겹침(F13): "시간이 겹쳐요" 확인 창에서 "돌아가기"를 고르면 대화상자로 돌아가고, "그래도 저장"을 고르면 3번으로 이어진다.
  - 저장 실패: 일정은 메모리에 남고 저장 오류 알림이 뜬다 (F11).
  - "저장"을 연달아 눌러도 한 번만 저장된다 (저장 중에는 버튼이 잠긴다).
- **사후 조건**: 새 일정이 목록·달력에 보이고, `data/schedules.csv`에 한 줄이 늘었다 (저장 실패 시 메모리에만 있음).

## F2. 일정 조회

- **시작하는 쪽**: 사용자
- **사전 조건**: 앱이 실행 중이다.
- **기본 흐름**
  1. 사용자: 사이드바에서 "오늘", "이번 주", "달력"을 고른다 (`Ctrl/⌘+1·2·3`) → 시스템: 해당 보기를 보여 준다.
  2. 시스템: 보이는 기간(오늘 / 월~일 / 한 달)의 일정을 반복 일정까지 날짜별로 펼쳐 날짜 → 시작 시간 → 제목 순으로 보여 준다 (F9).
  3. 사용자: "이전/오늘/다음" 버튼으로 기간을 옮기거나(이번 주는 한 주, 달력은 한 달씩), 달력에서 날짜를 고른다 → 시스템: 고른 날의 일정 목록을 보여 준다.
  4. 시스템: 각 일정에 상태(F6)와 카테고리를 함께 보여 준다.
- **대안 흐름**
  - 일정이 없음: "오늘은 일정이 없어요" + "새 일정을 추가해 하루를 채워 보세요"(오늘 보기), "이 날은 일정이 없어요"(달력), "이 달에는 일정이 없어요".
  - 카테고리·검색이 걸려 있어 결과가 없음: "조건에 맞는 일정이 없어요" + "검색어나 카테고리를 바꿔 보세요" (F7, F8).
  - 좁은 화면: 이번 주 보기는 요일 열 대신 아젠다로, 달력의 "고른 날" 패널은 격자 아래로 옮겨지고 점으로 표시된다.
- **사후 조건**: 데이터는 바뀌지 않는다. 고른 보기·날짜가 화면 상태로 남는다.

## F3. 일정 수정

- **시작하는 쪽**: 사용자 (일정 줄을 누르거나 `Enter`, 우클릭 메뉴 "수정")
- **사전 조건**: 수정할 일정이 화면에 보인다.
- **기본 흐름**
  1. 사용자: 일정을 고른다 → 시스템: 최신 상태를 다시 읽고, 기존 값이 채워진 "일정 수정" 대화상자를 연다.
  2. 사용자: 값을 바꾸고 "저장"을 누른다 → 시스템: 반복 일정이면 범위를 묻는다 ("반복 일정을 수정할까요?" — "취소" / "이 일정만" / "앞으로 전부").
  3. 시스템: F1과 같은 규칙으로 검증하고, 겹침(F13)을 확인한다. "이 일정만"이면 반복이 없는 값으로 검사한다.
  4. 시스템: 반복이 없으면 그 일정을 그대로 고치고, "이 일정만"이면 그 날짜 하나만 예외로 분리하고, "앞으로 전부"면 그 날짜부터 뒤의 반복을 새 값으로 바꾼다 (그 전 날짜는 그대로).
  5. 시스템: CSV에 저장하고(F11) "일정을 저장했어요" 토스트를 띄운 뒤 대화상자를 닫는다.
- **대안 흐름**
  - 입력 오류: F1과 같은 문구로 칸 아래에 안내하고 저장하지 않는다.
  - 취소: 대화상자의 "취소"/`Esc`, 또는 범위 선택에서 "취소" → 아무것도 바뀌지 않는다 (범위 선택에서 취소하면 수정 창은 열려 있다).
  - 그 사이 다른 곳에서 지워졌음: "이미 지워진 일정이에요" 토스트 후 창을 닫는다. 저장 직전에 사라졌으면 "일정을 찾을 수 없어요. 이미 바뀌었거나 지워졌을 수 있어요".
  - 시간 겹침: F1과 같은 "시간이 겹쳐요" 확인.
  - 저장 실패: F11.
- **사후 조건**: 바뀐 값이 모든 보기에 반영되고 CSV가 갱신됐다. "이 일정만"으로 고치면 원래 반복에서는 그 날짜가 빠지고(예외 날짜), 고친 값은 반복 없는 새 일정으로 생기며, 그 날짜가 이미 완료였다면 완료 상태도 새 일정으로 이어진다.

## F4. 일정 삭제

- **시작하는 쪽**: 사용자 (수정 창의 "삭제", 우클릭 메뉴 "삭제", 일정 줄에서 `Delete`/`Backspace`)
- **사전 조건**: 지울 일정이 화면에 보인다.
- **기본 흐름**
  1. 사용자: "삭제"를 누른다 → 시스템: 최신 상태를 다시 읽는다.
  2. 시스템: 반복이 없으면 확인 창 "‘제목’을(를) 삭제할까요?" ("삭제한 일정은 되돌릴 수 없어요.")를 띄운다.
  3. 사용자: "삭제"를 누른다 → 시스템: 일정을 지운다.
  4. 시스템: CSV에 저장하고(F11) 화면을 갱신한 뒤 "일정을 삭제했어요" 토스트를 띄운다.
- **대안 흐름**
  - 반복 일정: 2번 대신 "반복 일정을 삭제할까요?"로 범위를 묻는다 ("취소" / "이 일정만" / "앞으로 전부"). 별도 확인 창은 없다.
    - 이 일정만: 그 날짜 하나만 빠진다. 앞으로 전부: 그 날짜부터 뒤의 반복이 모두 사라진다.
  - 취소: 확인 창/범위 선택에서 "취소" → 삭제하지 않는다.
  - 이미 지워졌음: "이미 지워진 일정이에요" (이미 없으니 성공으로 본다), 저장 직전이면 "일정을 찾을 수 없어요. …".
  - 저장 실패: F11. 삭제는 메모리에서 유지된다.
  - 삭제 동작을 연달아 눌러도 한 번만 처리된다.
- **사후 조건**: 해당 일정(또는 범위)이 목록에서 사라지고 그 일정의 알림 카드도 치워진다.

## F5. 완료 처리

- **시작하는 쪽**: 사용자 (일정 줄의 체크, 우클릭 메뉴 "완료"/"완료 취소", 알림 카드의 "완료 처리")
- **사전 조건**: 일정이 화면에 보인다.
- **기본 흐름**
  1. 사용자: 체크를 누른다 → 시스템: 최신 상태를 읽어 완료 ↔ 미완료를 뒤집는다.
  2. 시스템: 그 날짜의 완료 기록만 바꾼다 (반복 일정은 날짜별로 따로).
  3. 시스템: CSV에 저장하고(F11) 화면을 갱신한다. 상태가 "완료"로 바뀐다(F6).
  4. 시스템: "일정을 완료했어요" 또는 "완료를 취소했어요" 토스트를 띄운다.
- **대안 흐름**
  - 이미 지워진 일정: "이미 지워진 일정이에요".
  - 알림 카드에서 이미 지워졌거나 완료한 일정: "이미 지워졌거나 완료한 일정이에요" 후 카드를 닫는다.
  - 저장 실패: F11.
- **사후 조건**: 그 날짜 일정의 상태가 완료(또는 완료 전 상태로 복귀)이고, 완료한 일정은 알림 대상에서 빠진다 (F10).

## F6. 상태 자동 계산

- **시작하는 쪽**: 타이머 (`StateRefreshTimer`, 1분마다). 화면을 그릴 때 사용자의 조작으로도 계산된다.
- **사전 조건**: 앱이 실행 중이다. 상태는 어디에도 저장하지 않는다.
- **기본 흐름**
  1. 타이머: 1분이 되면 → 시스템: 어제부터 7일 뒤까지의 하루치 일정을 지금 시각 기준으로 다시 계산한다.
  2. 시스템: 완료면 "완료", 시작 전이면 "예정", 시작~끝 사이면 "진행 중", 끝이 지났는데 미완료면 "지연"으로 정한다 (`StateCalculator`).
  3. 시스템: 지난번 계산과 비교해 바뀐 것이 있을 때만 화면에 알린다.
  4. 시스템: 화면이 현재 보기를 다시 그려 상태 표시를 갱신한다.
- **대안 흐름**
  - 바뀐 것이 없으면 화면을 건드리지 않는다.
  - 일정이 등록·수정·삭제·완료로 바뀌면 비교 기준을 그 상태로 다시 잡는다.
  - 날짜가 넘어가면 화면이 오늘 날짜를 다시 확인해 맞춘다.
- **사후 조건**: 화면의 상태가 지금 시각과 맞다. 데이터(CSV)는 바뀌지 않는다.

## F7. 카테고리 관리

- **시작하는 쪽**: 사용자 (사이드바 카테고리 "편집" → "카테고리 관리" 대화상자). 카테고리로 걸러 보기는 사이드바 목록에서 고른다.
- **사전 조건**: 기본 카테고리 수업·과제·팀플·개인이 있다.
- **기본 흐름 (추가)**
  1. 사용자: "새 카테고리 이름"에 이름을 쓰고 "추가"를 누른다 → 시스템: 앞뒤 공백을 지우고 1~20자인지, 이미 있는 이름인지(대소문자 무시) 검사한다.
  2. 시스템: 새 카테고리를 목록 끝에 넣고 `data/categories.csv`에 저장한다(F11).
  3. 시스템: 사이드바·대화상자 목록을 갱신하고 "카테고리를 추가했어요" 토스트를 띄운다.
- **기본 흐름 (이름 변경 / 삭제)**
  - 이름 변경: 사용자가 목록의 이름 칸을 고쳐 확정 → 시스템: 추가와 같은 규칙으로 검사하고 저장한다 (자기 이름 그대로는 허용).
  - 삭제: 사용자가 휴지통 아이콘을 누른다 → 시스템: "‘이름’ 카테고리를 지울까요?" 확인 ("일정 N개가 ‘개인’으로 옮겨져요." 또는 "이 카테고리에는 일정이 없어요.") → 사용자가 "삭제" → 시스템: 그 카테고리의 일정을 모두 "개인"으로 옮기고 일정 파일을 먼저 저장한 뒤 카테고리를 지우고 저장한다 → "카테고리를 삭제했어요".
  - 걸러 보기: 사용자가 사이드바에서 카테고리를 고르면(또는 "전체") 시스템이 그 카테고리 일정만 보여 준다 (F8과 함께 적용).
- **대안 흐름**
  - 입력 오류: "카테고리 이름을 입력해 주세요", "카테고리 이름은 20자까지 쓸 수 있어요", "이미 있는 이름이에요".
  - "개인" 삭제: 삭제 아이콘에 "‘개인’은 지울 수 없어요"가 표시되고, 직접 요청해도 "'개인' 카테고리는 지울 수 없어요".
  - 없는 카테고리: "없는 카테고리예요".
  - 삭제 확인에서 "취소": 아무것도 바뀌지 않는다.
  - 일정 파일 저장 실패: 옮긴 일정을 되돌리고 카테고리도 지우지 않는다 — "저장하지 못해서 카테고리를 지우지 않았어요". 카테고리 파일 저장만 실패하면 삭제는 유지하고 저장 오류만 알린다.
  - 걸러 보던 카테고리가 삭제되면 필터가 "전체"로 돌아간다.
- **사후 조건**: 카테고리 목록과 일정의 카테고리가 서로 맞고(없는 카테고리를 가리키는 일정은 "개인"으로 옮겨짐), 두 CSV가 갱신됐다.

## F8. 검색

- **시작하는 쪽**: 사용자 (검색창, `Ctrl/⌘+F`)
- **사전 조건**: 오늘·이번 주·달력 보기 중 하나이다 (주간 통계에는 적용되지 않는다).
- **기본 흐름**
  1. 사용자: 검색창에 글자를 입력한다 → 시스템: 입력이 멈춘 뒤(짧은 지연 후) 검색어를 앞뒤 공백을 지워 저장한다.
  2. 시스템: 제목 또는 메모에 검색어가 들어 있는 하루치 일정만 남긴다 (대소문자 무시).
  3. 시스템: 선택한 카테고리가 있으면 함께 적용(AND)한다 (F7).
  4. 시스템: 현재 보기를 걸러진 결과로 다시 그린다.
- **대안 흐름**
  - 결과 없음: "조건에 맞는 일정이 없어요 / 검색어나 카테고리를 바꿔 보세요".
  - 검색어를 지우면 전체가 다시 보인다. `Esc`는 글을 지우고, 비어 있으면(좁은 화면에서) 검색창을 접는다.
  - 주간 통계: 검색창이 꺼지고 "통계에는 검색이 적용되지 않아요"라고 안내한다.
- **사후 조건**: 데이터는 바뀌지 않는다. 검색어는 화면 상태로만 남는다 (앱을 닫으면 사라짐).

## F9. 반복 일정

- **시작하는 쪽**: 사용자 (등록·수정 대화상자의 "반복" 칸). 펼치기는 조회할 때마다 시스템이 한다.
- **사전 조건**: 일정 등록 또는 수정 중이다.
- **기본 흐름**
  1. 사용자: 반복을 고른다 — 반복 안 함 / 매일 / 매주(요일 기준) / 매월(날짜 기준) → 시스템: 반복 종료일 입력을 보여 준다.
  2. 사용자: 필요하면 "반복 종료일"을 켜고 날짜를 고른다 → 시스템: 종료일이 시작 날짜보다 이른지 검사한다.
  3. 사용자: 저장한다 → 시스템: 일정 하나 + 규칙으로 저장한다 (날짜마다 복사하지 않는다).
  4. 사용자: 보기를 연다 → 시스템: 보이는 기간 안의 날짜마다 하루치 일정(Occurrence)으로 펼쳐 보여 준다 (`RepeatExpander`).
- **대안 흐름**
  - 매월 31일처럼 없는 날짜가 있는 달은 건너뛴다.
  - 시작 날짜 이전, 종료일 이후는 만들지 않는다.
  - 종료일이 시작 날짜보다 빠름: "반복 종료일은 시작 날짜보다 빠를 수 없어요".
  - 수정·삭제할 때 "이 일정만 / 앞으로 전부"를 고른다 (F3, F4). "이 일정만"으로 저장하면 그 하루는 반복이 없는 별도 일정이 된다.
  - 완료는 날짜별로 따로 기록된다 (F5).
- **사후 조건**: 반복 일정이 규칙 한 줄로 저장되어 있고, 조회할 때마다 기간 안의 날짜로 펼쳐 보인다.

## F10. 알림

- **시작하는 쪽**: 타이머 (`ReminderTimer`, 30초마다)
- **사전 조건**: 일정에 알림(5분/10분/30분 전)이 설정되어 있다 ("알림 없음"이면 대상이 아니다).
- **기본 흐름**
  1. 타이머: 30초가 되면 → 시스템: 오늘·내일 하루치 일정 중 알림 시각(시작 − N분)이 된 것을 찾는다 (자정 직후 일정의 알림이 전날 밤이 될 수 있어 내일도 본다).
  2. 시스템: 앱을 켠 뒤~지금 사이에 알림 시각이 지났고, 완료하지 않았고, 아직 알리지 않은 것만 고른다. 알린 일정은 (일정 id + 날짜)로 기록해 한 번만 알린다.
  3. 시스템: 부르기 직전에 최신 일정을 다시 읽고, 남아 있고 미완료면 화면에 알린다.
  4. 시스템: 화면이 "곧 시작해요" 알림 카드를 띄운다 (카드는 직접 닫을 때까지 남고, 포커스를 가져가지 않는다). 설정에서 소리를 켰으면 소리를 내고, 창이 비활성이면 독/작업 표시줄이 깜박인다.
  5. 사용자: 카드의 "닫기" / "완료 처리"(F5) / "5분 뒤 다시"(F15) 중 하나를 고른다.
- **대안 흐름**
  - 앱이 꺼져 있던 동안 지난 알림은 보내지 않는다.
  - 이미 완료했거나 지워진 일정은 알리지 않는다. 카드가 떠 있다가 일정이 지워지거나 완료되면 카드를 치운다.
  - 같은 일정(같은 날짜)은 다시 알리지 않는다 (앱을 다시 켜면 기록은 초기화되지만, 켠 시각 이전에 지난 알림은 어차피 보내지 않는다).
  - 반복 일정은 날짜마다 따로 알린다.
- **사후 조건**: 알림 카드가 화면에 있고, 같은 일정·날짜의 알림은 기록되어 다시 나가지 않는다. 데이터(CSV)는 바뀌지 않는다.

## F11. 자동 저장 (시스템 내부 단계 — 유스케이스 아님)

사용자가 따로 하는 일이 아니라, 다른 기능이 데이터를 바꿀 때마다 시스템이 알아서 하는 **내부 단계**입니다. 유스케이스로 뽑지 말고 F1·F3·F4·F5·F7 명세 안의 한 단계로 넣으세요.

- **시작하는 쪽**: 시스템 (등록·수정·삭제·완료·카테고리 변경이 성공한 직후)
- **사전 조건**: 위 변경 중 하나가 메모리에 반영됐다.
- **기본 흐름**
  1. 시스템: 변경을 메모리 목록에 반영한다.
  2. 시스템: 전체를 임시 파일에 쓴 뒤 `data/schedules.csv`(카테고리는 `data/categories.csv`)로 바꿔 넣는다 (쉼표·줄바꿈이 있는 제목·메모도 따옴표로 감싸 안전하게).
  3. 시스템: 화면 리스너에 변경을 알려 보기를 다시 그린다.
  4. (다음 실행) 시스템: 두 파일을 그대로 불러온다. 파일이 없으면 예시 일정 5개(매주 반복 "팀플 회의" 포함)를 만들어 바로 저장한다.
- **대안 흐름**
  - 저장 실패: 메모리의 변경은 유지하고 "저장하는 중 문제가 생겼어요" 알림을 남긴다 (자세히 버튼: "저장하지 못했어요: 이유"). 카테고리 삭제는 예외로 되돌린다 (F7).
  - 불러올 때 읽지 못한 줄(형식 오류, F1 규칙 위반, id 중복)은 건너뛰고 "일정 파일 N번째 줄을 읽지 못해 건너뛰었어요 (…). 원본은 …-backup-날짜-시각.csv에 보관했어요"로 알린다. 따옴표가 깨져 파일 전체를 못 읽으면 일정을 불러오지 않는다.
  - 원본을 백업하지 못하면 읽지 못한 기록이 사라지지 않도록 그 파일에는 저장하지 않는다 ("…원본을 따로 보관하지 못해서 이 파일에는 저장하지 않아요").
  - 불러온 일정 중 없는 카테고리를 가리키는 것은 "개인"으로 옮긴다 (다음 저장 때 파일에 반영).
  - `data/app.lock`: 같은 데이터를 두 프로세스가 쓰지 않도록 앱이 이미 실행 중이면 "일정 관리가 이미 실행 중이에요. 열려 있는 창을 확인해 주세요."만 보여 주고 끝낸다.
- **사후 조건**: CSV가 메모리와 같다 (실패 시 다르고 알림이 남는다).

## F12. 빈 시간 찾기

- **시작하는 쪽**: 사용자 (사이드바 "빈 시간 찾기")
- **사전 조건**: 앱이 실행 중이다.
- **기본 흐름**
  1. 사용자: "빈 시간 찾기"를 누른다 → 시스템: 날짜·필요한 시간(30분/1시간/1시간 30분/2시간/직접)·찾을 시간대가 있는 창을 연다. 시간대는 설정의 "기본 활동 시간대"로 채워진다.
  2. 사용자: 날짜·필요한 시간·시간대를 정한다 → 시스템: 그날의 모든 일정(완료 포함, 카테고리·검색 필터는 무시)을 기준으로 비어 있는 구간을 시간 순서로 찾는다. 겹친 일정은 하나로 합쳐 계산하고, 오늘이면 지금 이후(5분 단위 올림)만 본다.
  3. 시스템: 구간마다 "10:00 – 12:00 · 2시간 비어 있어요"처럼 보여 준다.
  4. 사용자: 구간의 "이 시간에 추가"를 누른다 → 시스템: 창을 닫고 그 날짜·시작·끝이 채워진 새 일정 대화상자(F1)를 연다.
- **대안 흐름**
  - 빈 구간이 없음: "이 날은 빈 시간이 없어요".
  - 시간대 입력 오류: "시간대를 14:00처럼 시작이 끝보다 빠르게 입력해 주세요".
  - 필요한 시간은 15~480분으로 맞춰 계산한다 ("직접" 칸은 15~480).
  - 닫기/`Esc`: 구간을 고르지 않고 닫으면 아무 일도 일어나지 않는다.
- **사후 조건**: 데이터는 바뀌지 않는다 (구간을 골랐다면 F1이 이어진다).

## F13. 일정 겹침 경고

- **시작하는 쪽**: 사용자 (등록·수정 대화상자에서 "저장"을 누를 때 시스템이 검사)
- **사전 조건**: 입력값이 F1 검증을 통과했다 (검증 실패면 겹침은 검사하지 않는다).
- **기본 흐름**
  1. 사용자: "저장"을 누른다 → 시스템: 저장하려는 값과 같은 날짜에서 시간이 겹치는 다른 하루치 일정을 찾는다 (끝과 시작이 맞닿는 것은 겹침이 아니다).
  2. 시스템: 있으면 "시간이 겹쳐요 — 이 시간에 다른 일정이 있어요" 확인 창에 겹치는 일정들을 보여 준다 (많으면 "외 N개").
  3. 사용자: "그래도 저장"을 누른다 → 시스템: 저장을 이어 간다 (F1/F3의 저장 단계).
- **대안 흐름**
  - "돌아가기": 저장하지 않고 입력 창으로 돌아간다 (입력값은 그대로).
  - 겹침 없음: 확인 창 없이 바로 저장한다.
  - 수정 중인 자기 자신은 겹침으로 보지 않는다 ("앞으로 전부"면 자기 자신의 뒤 날짜도 제외, "이 일정만"이면 그 하루만 제외).
  - 반복 일정은 시작 날짜부터 28일 안의 하루치만 검사한다.
- **사후 조건**: 경고는 저장을 막지 않는다. 사용자가 고른 대로 저장되거나 저장되지 않는다.

## F14. 주간 통계

- **시작하는 쪽**: 사용자 (사이드바 "주간 통계", `Ctrl/⌘+4`)
- **사전 조건**: 앱이 실행 중이다.
- **기본 흐름**
  1. 사용자: "주간 통계"를 고른다 → 시스템: 보고 있는 날짜가 들어 있는 주(월~일)의 하루치 일정을 모은다 (반복은 펼친 개수, 카테고리·검색 필터는 적용하지 않는다).
  2. 시스템: 전체 일정 수, 완료한 수와 완료율, 지금 시각 기준 지연 수, 카테고리별 계획 시간 합, 요일별 일정 수를 계산한다 (`StatisticsCalculator`).
  3. 시스템: "전체 일정", "완료율", "지연", "카테고리별 계획 시간", "요일별 일정 수"로 보여 준다.
  4. 사용자: "이전/다음"으로 주를 옮긴다 → 시스템: 그 주로 다시 계산한다.
- **대안 흐름**
  - 그 주에 일정이 없음: "이 주에는 일정이 없어요 / 일정을 추가하면 계획 시간과 완료율을 볼 수 있어요" + "새 일정" 버튼.
  - 검색창은 쓰지 않는다 ("통계에는 검색이 적용되지 않아요").
- **사후 조건**: 데이터는 바뀌지 않는다. 일정이 바뀌면(F1·F3·F4·F5) 통계도 다시 계산된다.

## F15. 알림 다시 알리기

- **시작하는 쪽**: 사용자가 요청하고(알림 카드의 "5분 뒤 다시"), 시각이 되면 타이머(`ReminderTimer`)가 다시 알린다.
- **사전 조건**: F10 알림 카드가 화면에 떠 있다.
- **기본 흐름**
  1. 사용자: 카드의 "5분 뒤 다시"를 누른다 → 시스템: 일정을 최신 상태로 다시 읽는다.
  2. 시스템: 지금 + 5분을 다시 알림 시각으로 메모리에 예약하고 카드를 닫는다.
  3. 시스템: "5분 뒤에 다시 알려 드려요" 토스트를 띄운다.
  4. 타이머: 30초 확인에서 예약 시각이 지났으면 → 시스템: 예약을 지우고 "다시 알려 드려요" 카드를 띄운다 (한 번만).
- **대안 흐름**
  - 일정이 그 사이 지워졌거나 완료됨: "이미 지워졌거나 완료한 일정이에요" 후 카드를 닫는다. 예약 시각에 그런 상태면 조용히 버린다.
  - 다시 알림 시간이 1~60분을 벗어남: "다시 알림은 1분에서 60분 사이로 정해 주세요" (화면은 항상 5분을 쓰므로 일반 사용에서는 나오지 않는다).
  - 같은 일정에 다시 누르면 예약이 새로 덮어쓰인다.
  - 앱을 끄면 예약은 사라진다 (메모리에만 보관, 저장하지 않는다).
- **사후 조건**: 예약이 하나 늘었다가 시각이 되면 사라진다. 일정 데이터는 바뀌지 않는다.
