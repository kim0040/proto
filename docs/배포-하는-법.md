# 배포하는 법

Windows와 macOS용 앱을 GitHub Release로 내보내는 방법입니다.
태그 하나를 올리면 GitHub Actions가 앱을 만들어 Release에 붙여 줍니다.

## 1. 처음 한 번만: GitHub 저장소 연결

1. GitHub에서 빈 저장소를 만듭니다.
2. 이 폴더에서 아래를 실행합니다. (`<주소>`는 저장소 주소로 바꿉니다)

```sh
git remote add origin <주소>
git push -u origin main
```

3. GitHub 저장소의 Settings → Actions → General에서 Workflow permissions가 막혀 있지 않은지 봅니다.
   (워크플로가 Release를 만들 권한을 스스로 요청하므로, 보통은 따로 바꿀 게 없습니다.)

`main`에 올리거나 PR을 열면 `CI`가 돌아 세 운영체제(ubuntu, windows, macOS)에서 테스트를 합니다.

## 2. 새 버전 내보내기

1. `build.gradle`의 `version`을 올립니다. (예: `version = '1.0.1'`)
2. `docs/릴리즈-노트/1.0.1.md`를 만듭니다. (없어도 되지만, 있으면 Release 본문 맨 위에 들어갑니다)
3. 커밋하고 올립니다.

```sh
git commit -am "버전 1.0.1"
git push origin main
```

4. 태그를 만들어 올립니다. **태그는 `v` + `version` 그대로**여야 합니다.

```sh
git tag v1.0.1
git push origin v1.0.1
```

태그와 `build.gradle`의 `version`이 다르면 워크플로가 처음에 멈추고 이유를 알려 줍니다.
그럴 때는 `version`을 고쳐 커밋한 뒤, 태그를 지우고 다시 만듭니다.

```sh
git tag -d v1.0.1
git push origin :refs/tags/v1.0.1
```

## 3. 워크플로가 만드는 것

태그를 올리면 `Release` 워크플로가 아래 순서로 돕니다.

1. 태그와 `version`이 같은지 확인하고, 테스트를 돌립니다.
2. Windows와 macOS에서 앱을 만듭니다.
3. 두 결과를 모아 GitHub Release를 만듭니다. 변경 내용은 자동으로 채워집니다.

Release에 붙는 파일입니다.

| 파일 | 설명 |
| --- | --- |
| `ScheduleApp-<버전>-windows-x64.msi` | Windows 설치 파일 |
| `ScheduleApp-<버전>-windows-x64.zip` | Windows 휴대용 (풀어서 `ScheduleApp.exe` 실행) |
| `ScheduleApp-<버전>-macos-arm64.dmg` | macOS 설치 파일 |
| `ScheduleApp-<버전>-macos-arm64.zip` | macOS 휴대용 (풀어서 `ScheduleApp.app` 실행) |

- macOS 앱은 **Apple Silicon(M1 이후, arm64) 전용**입니다. GitHub의 `macos-latest` 러너가 arm64이기 때문입니다. Intel Mac용은 만들지 않습니다.
- Windows 앱은 x64용입니다.
- 앱 안에 자바가 들어 있어서, 받는 사람이 자바를 따로 깔지 않아도 됩니다.

### 연습 실행 (Release 없이)

Actions 탭 → Release → Run workflow를 누르면 앱만 만들어 줍니다. Release는 만들지 않습니다.
결과는 그 실행 페이지 아래쪽 Artifacts에서 받을 수 있습니다. 태그를 올리기 전에 빌드가 되는지 볼 때 씁니다.

## 4. 내 컴퓨터에서 직접 만들기

JDK 17 이상이 필요합니다. jpackage는 지금 Gradle을 돌리는 JDK의 것을 씁니다.
다른 JDK를 쓰려면 `-PpackagingJdk=<JDK 경로>`를 붙입니다.

| 명령 | 결과 |
| --- | --- |
| `./gradlew jpackageImage` | 앱 이미지 (`build/jpackage/image/`). macOS는 `ScheduleApp.app`, Windows는 `ScheduleApp` 폴더 |
| `./gradlew packageZip` | 앱 이미지를 zip으로 묶음 |
| `./gradlew jpackageInstaller` | macOS는 dmg, Windows는 msi |
| `./gradlew jpackageImage packageZip jpackageInstaller` | 위 셋을 한 번에 |

- 최종 파일은 `build/dist/`에 `ScheduleApp-<버전>-<os>-<arch>.<확장자>` 이름으로 모입니다.
- Windows에서 msi를 만들려면 [WiX Toolset 3](https://wixtoolset.org/)이 필요합니다. (GitHub Actions의 Windows 러너에는 들어 있습니다)
- macOS에서는 `jpackageImage`가 끝나면 임시(ad-hoc) 서명을 자동으로 합니다.
- 아이콘을 바꿨다면 `packaging/make-icons.sh`로 `.icns`와 `.ico`를 다시 만들고 커밋합니다.
- 앱 이름은 파일 이름 안전을 위해 영문 `ScheduleApp`입니다. 화면과 macOS 메뉴 막대에는 "일정 관리"로 보입니다.

## 5. 받는 사람에게 알려 줄 것

앱에 Apple·Microsoft의 정식 서명이 없어서, 처음 열 때 경고가 뜹니다. 아래대로 하면 열립니다.

### macOS

1. dmg를 열어 `ScheduleApp`을 Applications 폴더로 끌어 놓습니다. (zip이면 풀어서 원하는 곳에 둡니다)
2. 처음에는 더블클릭하지 말고 **Finder에서 앱을 우클릭 → 열기**를 누르고, 뜨는 창에서 다시 "열기"를 누릅니다.
3. 그래도 막히면 **시스템 설정 → 개인정보 보호 및 보안**으로 갑니다. 아래쪽에 "ScheduleApp이(가) 차단되었습니다"가 보입니다. **그래도 열기**를 누릅니다.
4. 터미널을 쓸 수 있다면 한 줄로도 됩니다.

```sh
xattr -dr com.apple.quarantine /Applications/ScheduleApp.app
```

한 번 열고 나면 그다음부터는 그냥 더블클릭하면 됩니다.

### Windows

1. 설치 파일(msi)이나 `ScheduleApp.exe`를 실행하면 "Windows의 PC 보호" 창(SmartScreen)이 뜰 수 있습니다.
2. **추가 정보**를 누르면 **실행** 버튼이 나옵니다. 누르면 됩니다.
3. msi는 현재 사용자에게만 설치됩니다(관리자 권한이 필요 없습니다). 설치 위치는 고를 수 있고, 시작 메뉴와 바탕화면에 바로가기가 생깁니다.

## 6. 데이터가 저장되는 곳

설치한 앱은 실행 위치를 알 수 없어서, 운영체제가 정한 사용자 폴더에 저장합니다.

| 운영체제 | 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/ScheduleApp` |
| Windows | `%APPDATA%\ScheduleApp` (보통 `C:\Users\<이름>\AppData\Roaming\ScheduleApp`) |
| 그 밖 | `~/.scheduleapp` |

- 이 폴더 안에 `schedules.csv`, `categories.csv`, `app.lock`이 생깁니다. 서버 설정을 쓰면 `server.properties`도 여기에 둡니다.
- 설정 화면의 "데이터 폴더"에서 위치를 보고 "폴더 열기"로 열 수 있습니다.
- 앱을 지워도 이 폴더는 남습니다. 완전히 지우려면 이 폴더도 지웁니다.
- `./gradlew run`으로 켠 개발용 앱은 지금처럼 프로젝트의 `data/`를 씁니다.
- 폴더를 직접 정하려면 실행 옵션 `-Dproto.dataDir=<폴더>`를 줍니다. 이 값이 가장 먼저 쓰입니다.

## 7. 아직 확인하지 못한 것

- Windows(msi·zip·실행)는 이 문서를 쓴 Mac에서 돌려 보지 못했습니다. 첫 Release 전에 연습 실행으로 한 번 확인하세요.
- Intel Mac용과 Linux용은 만들지 않습니다.
